# Contributing

```sh
pnpm install
pnpm test       # unit and type tests, watch mode
pnpm check      # everything CI runs: generated files, lint, typecheck, tests, build, smoke test
pnpm generate   # regenerate files derived from the style spec and the JSDoc examples
```

Add a changeset (`pnpm changeset`) to any PR that changes behavior. See [Releasing](README.md#releasing).

## Layout

- `src/expr.ts`: the core types (`Expr`, `ExprLike`, `Input`, `Color`, ...) and `toSpec`.
- `src/internal.ts`: the `op()` array builder and build-time checks. Not exported.
- `src/operators/*.ts`: one function per spec operator, grouped as in the spec docs.
- `src/recipes.ts`, `src/accessors.ts`, `src/global-state.ts`: helpers built on the operators.
- `src/testing.ts`: the `/testing` entry. It bundles `@maplibre/maplibre-gl-style-spec`, which is a dev dependency only.
- Generated by `pnpm generate`: `src/operator-names.ts`, `src/style-properties.ts`, `test/jsdoc-examples.generated.ts`.

## Type design rules

These keep type-checking fast and the types honest. Breaking them tends to look fine in a small test and then cost users seconds per call site.

- **Never use `ExpressionSpecification` in a signature, and never intersect with it.** It's a union of about 90 recursive tuple types. `Expr<T>` is `["literal", unknown] & Typed<T>`, a single member of that union, so results stay assignable to MapLibre's types without TypeScript comparing the union pairwise. Parameters use the cheap `ExprLike<T>`.
- **Value-typed getters return `Expr<NoInfer<T>>` with `T = any`** (`get`, `featureState`, `globalState`, `var_`, `accumulated`). Inferring their type from context breaks overload resolution and generic callers.
- **Branch operators infer their output from the first branch** and take the rest as `NoInfer<T>`, as MapLibre does. Each also has a color overload so CSS color strings and color expressions mix.
- **Every exported function has an explicit return type** (`isolatedDeclarations`), JSDoc that names its operator ("MapLibre \`op\`.") and an `@see` link to the operator's heading in the spec docs.
- **Reserved words get a trailing underscore**: `case_`, `in_`, `let_`, `var_`, `typeof_`.
- CI fails the typecheck if it takes over 60 seconds; it normally takes under one.

## Tests

- Test behavior by evaluating with `evaluate()` from `src/testing.ts`, not by comparing array shapes, except where the emitted JSON itself is the point.
- Compute expected values independently of the engine (geodesy, formulas), so a test can catch the engine being wrong too.
- `test/coverage.test.ts` keeps the wrappers, the spec's operator list, the platform notes and the README's operator table in sync.
- Tests named "upstream quirk" assert current MapLibre bugs. When one fails after a spec update, MapLibre fixed the bug: update the test and the matching doc note.

## Adding a spec operator

1. Update `@maplibre/maplibre-gl-style-spec` and run `pnpm generate`.
2. Add the function, with JSDoc, an `@example` and an `@see` link.
3. Add it to `WRAPPERS` in `test/coverage.test.ts` and to the README's operator table.
4. Add an evaluation test in `test/operators.test.ts`.
5. If the spec lists platform limits for it, add the note; the coverage test says what's expected.
